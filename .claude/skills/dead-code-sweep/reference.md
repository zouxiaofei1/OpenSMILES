# 死代码清扫：踩过的坑与实现要点

## 变异法三个致命坑（都实测踩过）

### 1. `.pyc` 秒级校验会静默测错变异体

CPython 的 pyc 头只存源文件 **mtime（秒）+ size**。而同一文件的不同变异体插入的字符数
**完全相同**（`return None\n` + 缩进，与插入位置无关），所以同一秒内跑的两个变异体
`(mtime, size)` 一模一样 → 第二个直接复用第一个的 pyc → **静默地在测错误的变异体**，
而且完全不报错。

对策（`sweepcfg`/`sweep_drive.py` 已内置）：
- 所有子进程 `PYTHONDONTWRITEBYTECODE=1`；
- 建树时清掉归档里带来的 `__pycache__`；
- 别在同一秒内对同一文件跑两个变异体（脚本串行执行，天然满足）。

### 2. 覆盖率不能与变异扫描并发采

第一次的覆盖率是在后台扫描跑着时采的：工作树的 src 正被反复改写/还原，采到的是
**掺杂了变异体的混合状态**（920 个函数 vs 干净的 991 个）。后果是出现
「从未执行却被判定为改变了预测」的假矛盾——看起来像方法不自洽，其实是测量被污染。

对策：任何 src 相关测量（覆盖率、基线、pytest）都不与变异扫描并发。

### 3. 还原必须按字节

`Path.read_text()` / `write_text()` 在 Windows 上会把 LF 翻成 CRLF。逐字节比对时
整个文件都会显示「不同」，看起来像还原失败。对策：`read_bytes()` / `write_bytes()`，
并用 `mutlib.verify_clean()`（md5 快照）确认。

## 其他实现要点

- **兼容垫片必须排除**。旧快照把 `normalize_en/normalize_zh/nospace` 放在
  `tools/re.py`（新版在 `constants.py`），评测脚手架顶层 import 它们。为跑通要加垫片，
  但注入 `return None` 会让 `None == None` 恒成立 → **分数虚高到 100%**。
  这 3 个必须写进 `sweep.json` 的 `shims` 从候选里剔除。
- **预导入检查要放在脚手架 import 之前**。`benchmarks.benchmark` 顶层就 `import namepredict`，
  若把「试导入」放在它后面，导入期崩溃会逃逸成 `runner_crash` 而不是 `import_error`。
- **导入期必需 ≠ 死**。例：`fg_registry.srs_fgs` 的结果在 `stereo.py` 模块级参与
  `_RS_KINDS = _fg_reg.srs_fgs() | frozenset(...)`，注入后直接 TypeError。
  同理 `anchored_table._canon` 在建表时被调用。这类函数覆盖率若在 import 之后才装监控
  会漏记「仅导入期调用」——**覆盖率必须早于包导入**。
- **早期退出是性能关键**。按覆盖度贪心排序探针行序后，前 10 行即覆盖 96% 的被执行函数，
  单个变异体从「全扫 4.9s」降到「0.7s」。命中早的函数几乎零成本。
- **逐行预测比总分敏感**。总分不变可能只是因为改动只落在本来就失败的行上。
  用逐行 `(en, zh)` 比对，附带记录首个不同行的 base/mut 判分，能直接看出是「修好了」
  还是「改坏了」。
- **行长打满的 debug print**：管线里有遗留 `print`，会淹没输出。worker 里
  `sys.stdout = open(os.devnull, "w")`；主进程解析子进程输出时按行过滤 `progress`。

## 静态法（选项 1）的已知盲区

这些在引用图里看着是死的，其实活着，**必须靠变异法或全量验证复核**：

- **装饰器注册**：`@_register("x")` 修饰的顶层函数，注册即使用。
- **转口 import**：`A 从 B import f`，C 又从 A `import f`。删 B 的 import 前必须 grep
  还有谁在转口（删错会导致大批 collection error）。
- **注册表 / probe 元组成员**：`_HANDLERS = [FnHandler(topo.match_halo)]`、
  `_TOPOLOGY_SIDE_PROBES` 这类顶层表达式引用的 def。若只遍历 def body 建图会全漏，
  把活函数误判死。
- **调用图闭包要迭代**：删一个函数后其唯一 callee 变死，死链会传播。
- **契约测试保护**：`_HELPERS = {...}` 断言 `hasattr(mod, h)`、`enum_names={...}` 这类
  字符串集合，会让生产不用的函数也不能删。扫下游时要用**纯文本**匹配（连字符串一起命中），
  不能只做 AST。
- **同名假引用**：多个模块各自定义同名的 `_heavies` 之类，跨模块按名匹配会把它们互相
  当引用。宽松匹配是**安全方向**（宁可漏判死，不可误删活），但要意识到会高估存活率。

## 下游引用扫描的坑

- 扫 `tests/` / `benchmarks/` 时若目录不存在，`rglob` 会**静默返回空** → 全部误报「零引用」。
  脚本要先 `is_dir()` 判断；发现「全库零引用」比例异常高时，先怀疑路径配错。
- `tools/<pkg>-v2`、`tools/<pkg>-v3` 是**独立引擎副本**，不是本包的下游，要排除，
  否则会把另一个代码库的同名函数当成调用方。
- 扫的是**主仓库**（`sweep.json` 的 `repo`），不是工作树——工作树里没有上游的
  `server/`、`tools/`。

## 判定口径

- 只被测试引用的，**按项目既定口径不算死代码**（删除即 fail 测试）。要么同步改测试，
  要么保留，并在报告里列进「需同步修改下游」那一栏。
- 「从未执行」永远要带口径：这是在这份 benchmark 的输入分布下没被用到，
  **不等于绝对死代码**。基准覆盖不到的结构形态仍可能触达。
- B 类（执行过但注入无效果）不是「没跑到」，是「跑到了但结果没人用/被下游覆盖」。
  删之前确认那条分支不会让别的输入退化——例如被更早分支抢答后的兜底路径。
