# 命名改进机会审计

目标是找到值得修的**共同根因**，不是堆积错误样本。默认只运行、分析和提出方案，不修改生产代码、测试、金标或评分逻辑。自然语言参数可指定数据集、重点、时间预算和建议数量；默认给出 3–5 个经验证建议，证据不足时宁缺毋滥。

**范围分支：** 用户明确要求局部分析、复用指定基线、禁止全量/并行或限制预算时，以该限制为准，跳过冲突步骤；预算按实际底层工具调用计数。保留可完成的证据检查，将未做的全量、视角、独立反证及第二轮逐项披露，报告标为“局部审计”，不冒充完整流程。

## 1. 建立可复现基线

读取当前项目指令、`git status`、benchmark CLI 与计分实现。只由协调者运行一次全量，subagent 共享本轮产物，不各自重复全量。临时脚本、日志和报告放**仓库内** `tmp/` 或 `tools/`，每轮创建新的子目录，勿覆盖已有产物。

```bash
python -m benchmarks.benchmark_parallel --data data/merged_benchmark.json --time --timeout 1 --snapshot tmp/namer-audit/<run-id>/snapshot.json
```

将 `<run-id>` 替换为本轮唯一目录名。记录 commit、工作区差异、数据路径及哈希、命令、时间、EN/ZH/dual 的分子分母。保留原始日志和逐行结果；需要完整 report 时，在临时脚本中调用 `run_benchmark_parallel`，用 `json.dump` 保存返回对象。Windows 多进程脚本需要 `if __name__ == "__main__":`。

当前接口陷阱（使用时复核源码）：
- `--json` 的 stdout 混有进度文本，且省略 `results`；不可把整个 stdout 当 JSON。快照为 `items` 映射，不是完整 report；按原数据补齐 source/tier/eval 标志，检查重复 key，保留原始行号。
- dual 表示该行**启用的字段**全通过；中文分母可能更小，`None` 不是失败。分数是规范化字符串匹配，不等于化学正确率。
- 每行清空 cache；复现使用新 `SMILESNNamer` 或同等 cache 隔离。保留输入 SMILES 原子序，分析去重不能改变复现输入。
- 当前 `as_completed` 后的 `result(timeout=...)` 不构成硬超时；空名也不等于超时。异常/疑似卡住案例单独限时隔离复现，保存 `success`、错误和 metadata。

## 2. 分层抽样，建立失败地图

覆盖整个失败集的廉价统计，再按 source、tier、EN/ZH、空名/异常/残缺/非空失配、结构特征交叉抽样。按**化学结构与共同根因**聚类，名称关键词仅用于找候选。保留多标签及簇交集；不能将所有标签计数相加作为收益。

| 类别 | 判定依据 |
|---|---|
| A：空间内 bug | 当前代码与测试已支持此结构族，某组合、编号、表达或边界实现错误 |
| B：空间扩展 | 需要新增母体、官能团、拓扑、价态或命名机制；说明新增能力及依赖 |
| C：非命名缺陷/待裁决 | 金标、合法异名、PIN 与 general 模式差异、评分或运行环境问题 |

`in_scope` 文件名、tier 和 `success=True` 都不能单独证明支持边界。边界不清则标“待定”，先查实现、测试和限制，不能把所有空名归为扩展。C 单列，不占 A/B 建议名额。

## 3. 多角度 subagent 调查

同时启动以下 4 个只读分析 subagent，共享基线、失败地图、运行目录和统一证据卡；分配互补切片，避免重复扫描。工具不可用或 agent 失败时重试一次或由协调者补齐，并披露覆盖缺口，不能假称已并行验证。

| 视角 | 调查重点 |
|---|---|
| 化学规则与金标 | 本地 IUPAC、PIN/general、合法异名、双语与真正结构错误 |
| 空间内根因 | L0–L5 数据流，首个错误中间表示；元素、键级、原子覆盖、编号、立体化学 |
| 空间扩展 | 频繁缺失结构族、现有基础设施可复用性、最小可交付支持边界 |
| 收益与回归 | 失败簇规模、近邻已正确样本、跨层影响、组合规则、性能和测试缺口 |

每个 subagent 返回下节证据卡，不直接修复。协调者按根因合并后，交给**未提出该结论**的 subagent 反证：尝试找合法异名、上游保证、已修路径、近邻误伤及错误归因。反证者实际重跑代表例并阅读代码/规则，不只给意见。

规则裁决顺序：本地 `docs/iupac/cn_translated/` 的适用条款 > 验证测试集 > 网络来源 > namer 输出。记录条款与文件位置；未找到条款或名称期望未裁决就标待验证。原子覆盖完整不证明元素、键级、连接或立体化学表达正确。索引类问题额外验证原输入 atom-id/locant 映射、盐片段映射及冷暖缓存，不能只断言名称。

## 4. 每个建议的必填证据卡

1. **结论与分类**：标题、A/B/待定、置信度、规则依据、支持边界证据。
2. **复现**：benchmark 行号/id、原始 SMILES、实际 EN/ZH、金标、裁决后的期望；命令及输出文件。深挖候选抽 3–5 个代表失败和至少 1 个已正确近邻反例，数量不足据实说明。
3. **根因与改法**：已读取的 `文件:行号`、函数、L0–L5 调用链、首个错误字段/条件；具体修改哪个判定、数据传递或组装规则，以及哪些行为必须保留。可疑位置与已证根因分开。
4. **收益**：候选簇总数、实际验证数、确认同因数、与其他建议重叠数；分别报告 EN/ZH/dual 潜力。无补丁时只有估计，不能声称已修复 N 条。未知影响面写未知；降低错误成功率可有价值，即使严格分数不升。
5. **成本与风险**：低/中/高及理由，依赖层/接口、最危险近邻、可能退化的已正确结构族、性能；B 必须给最小增量边界和暂不支持的组合。
6. **验收与反证**：建议测试文件/函数、正例及负例 SMILES、后续 pytest 与全量 benchmark 验收；独立复核结论（确认/否定/待验证）及证据缺口。

排序以“确认影响面 × 置信度 × 用户价值”相对于实现/验证成本和回归风险判断，不强造精确分数。优先局部、可泛化、规则明确、反例可控的修复；高收益低风险的 B 可以优于 A。共享母体排序、通用递归、原子索引和覆盖门控的变更须说明较大影响面。

## 5. 收敛与交付

第一轮后让独立 subagent 检查遗漏的高频簇/结构族。对缺口做定向第二轮；新增建议也必须反证。默认两轮，用户明确要求更深时追加。记录扫描范围、抽样方法、未调查簇及停止原因，不能把抽样称为穷尽。

报告依次输出：基线与评分语义；按收益风险排序的 3–5 项 A/B 建议表；每项证据卡；C 类/被否定/暂缓项；首选行动及未验证内容。详细材料放运行目录，正文保持可扫描。没有足够证据时只给已确认项和调查缺口，不凑数。

## 常见误判

| 诱惑 | 正确处理 |
|---|---|
| “关键词命中 34 条，所以可修 34 条” | 候选数与同因确认数分列，抽查多种结构与簇重叠 |
| “代码看起来违反规则，先排高优先” | 未复现的静态疑点进入待验证，不混入已确认建议 |
| “简单环加模板就是空间内修复” | 用既有支持边界裁决，缺失能力可能属于 B |
| “先把名字改成 gold，提高分数” | 先查 IUPAC、命名模式和结构语义，不改评分/金标掩盖错误 |

红旗：没有原始 SMILES；没有已读代码锚点；没有近邻；把全簇当实测收益；把 `success` 或 coverage 当化学正确；只检查前 N 行；并行 agent 重复跑全量。出现时补证或降级，不提交貌似完整的结论。

默认至此停止。用户另行授权实现后，**必须使用 `chem-tdd-skill`**，先红后绿，再做全量回归。禁止单 SMILES 特判、为过分数放宽规则、未经同意移除命名管线调试输出或全局 canonicalize 输入。
