# chem-brainstorm-skill

选题前 **证据型** 分析：先读后判，产出「一轮 vs 分轮 + 顺序」，若结论为应当多轮完成，则写入 `workstate.md` → `## 其他`。

**Core principle:** 没有读完（workstate / 代码 / IUPAC）不得给实现顺序；没有命名空间地图不得说「一轮做完」。本 skill 对 **任意** 化合物类/规则族通用，禁止把某一族的特例写成默认流程。

**编排位置：** 在 `prompt.txt` 步骤 2（选题）之前；交付「下一轮」与（若分轮）长期路线后，才进入 `chem-tdd-skill`。实现后审查 → `chem-code-review`；全局架构债 → `analyzing-architecture-risk`。

## 何时用 / 不用

**用：**

- 新开一类物质/一族规则，或 first-cut 后要扩全族
- 问：完全命名可能、变体是否连做、架构能否统一、接入点、几轮
- workstate 候选空，或用户给了「分析清单 / 分割线」要调度决策

**不用：**

- 已定题只实现 → `chem-tdd-skill`
- 只审 diff / dual → `chem-code-review`
- 无具体规则族的纯可维护性审计 → `analyzing-architecture-risk`
- 通用产品 brainstorm（本 skill 以仓库证据为准，不追问空泛「目的是什么」）

## 硬门禁

1. **必读信息**（可并行）：`workstate.md`、相关 `src/namepredict/layer0–5/**`、`docs/iupac/**`（条款号 + PIN/例句）
2. **禁止写生产代码**；此时不改 `src/namepredict/**`
3. **分轮必须落盘**：顺序写入 `workstate.md` → `## 其他`；
4. **禁止族特化模板**：流程、表头、判定标准必须抽象；举例最多一句且标「例」，不得写成唯一路径

## 工作执行流程（按序）

### Phase 0 — 锁定靶心

Brainstorm：

| 字段 | 含义 |
|------|------|
| 主类 | 要分析的化合物类 / 规则族（用户用语） |
| IUPAC 锚点 | 主条款（及紧密附属条款） |
| 用户清单 | 若有分割线/六问等，降为 **内部检查表**，不逐条灌水长答 |

内部六问（可增删，勿当用户可见大纲）：

1. 现状  2. 完全命名空间  3. 变体连做  4. 架构统一  5. 实现步骤  6. 可接入点

### Phase 1 — 阅读信息（不写结论）

| 步 | 读什么 | 最低证据 |
|----|--------|----------|
| 1.1 | `workstate.md` 日志尾 + `## 其他` | first-cut / 已有路线 / 禁忌 |
| 1.2 | 代码：与主类相关的 L1 检测、L2 parent/kind、L3 前缀、L4 编号、L5 组装；注册表（kind / producers / 分发） | 已有 kind、互斥门控、覆盖范围、复制粘贴兄弟 |
| 1.3 | IUPAC 对应章条 + 表 | 后缀/前缀/功能类名、PIN 例、置换/同源规则 |

**搜法（抽象）：** 用主类英文/中文关键词、条款号、已有 kind 名、词缀（…ic acid / …ate / …yl …）在代码与 `docs/iupac` 中交叉定位。禁止只靠记忆。

### Phase 2 — 命名空间地图

对本主类画出系统命名格子，**按本类实际结构选维度**（缺则标 N/A，勿硬套他族字段）：

| 维度 | 要回答 |
|------|--------|
| 命名操作/形态 | 取代后缀、功能类、前缀、保留名、盐/离子… 本类用哪些 |
| 主骨架/母体侧 | 链长、支化、环、芳/稠、杂环；first-cut 砍到哪 |
| 次臂/连接侧 | 若有酯 O、酰胺 N、盐金属、多位点等：允许什么取代 |
| 立体/不饱和 | E/Z、R/S、ene/yne 是否本族职责 |
| 多官能主次 | 如何与其他模块相连接 |
| 内酯/环状特例、置换类似物、稀有同源 | 必须列出计划，明确何时做 |

### Phase 3 — 变体轴（该不该连做）

从 IUPAC 与代码兄弟模块 **归纳** 本族的正交轴（下列为常见轴类型，**按命中选用**，非检查表全做）：

| 轴类型 | 抽象含义 | 默认可连做？ |
|--------|----------|--------------|
| 衍生物/离去模式 | 同一母核不同主特性表达（酸/酯/酰胺/酰卤…） | 已有平行 kind 时优先 **横扩缺口最大者**；公共抽取另轮 |
| 氧化态/价态 | 同元素不同词缀族 | 检测与词缀不同 → **新 first-cut 轮** |
| 元素同源 | 周期表同族替换（词根替换） | 至少保证拓展性 |
| 骨架复杂度 | 更长链、支链、环、稠环 | 与现门控同构则可连做 |
| 次臂复杂度 | 另一侧特殊烷基/芳基 | 若已有共享分类器可挂 → 倾向连做 |
| 前缀 vs 后缀 | 他基团优先时的前缀模式 | 常依赖主路径稳定 → 远期 |
| 环内/桥连特例 | 内酯、sultam 类、桥环特则 | 常换路径（杂环等）→ 远期 |
| 跨族类比 | 另一大类酸/酯/磷/硼… | 只共享 **词表级/侧链分类级**；禁止 L1/L2 硬合并无共用 IR 的族 |

对每条命中轴标注：**同轮 / 下轮 / 远期** + 一句理由。远期仍需规划+完成

### Phase 4 — 架构统一判断

| 档 | 判据 | 动作 |
|----|------|------|
| 短期 | ≥2 模块同构复制，抽公共 **不改对外命名语义** | 可排独立「去重轮」；dual 允许持平 |
| 中期 | 需参数化/注册表化才能降边际成本 | 记 workstate，不本轮夹带 |
| 勿做 | 无共用检测 IR 却强行一套 parent 引擎 | 明确拒绝并写原因 |

统一 **时机** 必须可执行，禁止「将来自然统一」。

### Phase 5 — 接入点

只列 **仓库里已存在** 的路径/符号 + 一句话用途。类别提示：

- L0 预处理/盐
- L1 检测条目
- L2 母体/kind/候选生产者、已有 walk/侧链分类
- L3 取代基/叶
- L4 编号/位次
- L5 词干/组装/分发
- 测试模板与近邻负例所在

禁止把「计划中的新框架」写成接入点。

### Phase 6 — 一轮 vs 分轮

**一轮做完** 条件：

1. 单一主条款（或检测+组装紧密一对）
2. 需动代码的正交轴 ≤1
3. 无「必须先大拆架构才能横扩」的硬依赖

否则 **分轮**，给出有序：

### Phase 7 — 落盘与收口

- **分轮：** 按照输出模板写 `workstate.md` → `## 其他`
- **一轮：** 继续工作流，调用subagent开始实现

## 输出模板: 按此格式输出workstate.md **其他** 节

```markdown
## 选题: [ ]

### 现状: [ ]
(处于哪个round?代码状态如何?)

### 做法或顺序
Round A: [范围 / 何时做 / 如何做 / 接入点 / 禁止项 / 预计影响 / ... ]
Round B: [... ]
Round C: [... ]
...
------------------------------------
```
(全部完成后删除整段。其他中可同时存在多个选题，如果需要。)
## 反模式

| 借口 | 现实 |
|------|------|
| 先写码再分析 | 停写，回 Phase 1 |
| 一族全做才有 dual | 跨轴大包；必须分轮 |
| 无样本就跨族抽象 | 过早统一；记中期/勿做 |
| IUPAC 我记得 | 必须打开条款与 PIN |
| 分轮不写 workstate | 下 session 失忆 |
| 只答清单不问调度 | 缺主答：一轮/分轮 |
| 接入点写未来模块 | 只列现存代码 |
| 把某族字段当全站必填 | 维度按本类裁剪，N/A 显式 |
| 稀有复杂和不涨准确率的结构不用做 | 未来什么都要做，可以标远期暂缓 |
| 看不清楚的远期随便写即可 | 至少要写明已知信息和触发条件(何时进一步研究，何时开始做?) |
| 远期规划没用 | 大多数项目都需要长期蓝图，全面规划多个Round对项目有利 |

**命中 → 停，补 Phase，再结论。**

## 检查清单

- [ ] 来源已读；结论有路径/条款依据
- [ ] 命名空间含已覆盖/缺口/远期
- [ ] 变体轴从本类归纳，非他族拷贝
- [ ] 架构统一有时机档
- [ ] 接入点均为现存路径
- [ ] 一轮或分轮明确；分轮已写 `## 其他`
- [ ] 未改 `src/namepredict/**`
- [ ] 下一轮粒度可过选题审查
- [ ] 全文无「只适用于某一化合物族」的硬编码流程
- [ ] 暂时无完成条件的项目也已经规划了蓝图
- [ ] 此蓝图已经足够详细，未来的工作者能根据其逐步实现这一主题的完整命名规则
